# Exploratory AIT rate-score adaptation

Declared 26 October 2026 before running this added comparator. The original 157-candidate registry and primary tests are unchanged. Include the result regardless of performance; this is an adaptation, not a replication or a matched-input formula contrast.

Source: Landauer et al., AIT Alert Dataset paper, Appendix A, https://www.skopik.at/ait/2024_cset.pdf; implementation inspected at https://github.com/ait-aecid/alert-data-set/blob/main/analyze.py (score aggregation) and attacktimes.py (normal windows), accessed 26 October 2026.

For native key q, phase p and fitting scenario s, let A be the number of alerts in p, B the number in the fixed normal window, and Dp and Db the corresponding durations. The phase/scenario contribution is 0 if A=0, otherwise max(0, 1 - (B/Db)/(A/Dp)). The phase score is the sum of contributions divided by the number of fitting scenarios where the phase exists, including zero-attack-count scenarios. The key score is the maximum phase score. If no fitting phase exists the score is zero. Missing/previously unseen keys receive zero. No severity multiplier, calibration, clipping, tuning, or thresholding is added.

Normal windows are UTC, half-open, taken from the published implementation: fox 2022-01-17 11:00–16:00; harrison 2022-02-07 05:00–09:00; russellmitchell 2022-01-23 01:00–06:00; santos 2022-01-16 10:00–15:00; shaw 2022-01-28 12:00–17:00; wardbeck 2022-01-22 10:00–15:00; wheeler 2022-01-29 07:30–18:00; wilson 2022-02-06 13:00–18:00. Thus the implementation uses 4 and 10.5 hours for harrison and wheeler; do not assume every window lasts five hours. Windows must lie inside each trace and not overlap attack intervals.

Declared departures: the published analysis pools detector abbreviations and aggregates all eight scenarios for filtering. This adaptation uses the manuscript's 93 (detector, native-key) identifiers and fits seven training scenarios only, then assigns a fixed key score to each alert in the eighth. This aligns the unit with the manuscript's identifier analysis while retaining the published rate and cross-scenario support construction. It uses extra normal-window/duration information, so cannot isolate a formula effect within the original common-input block. The maximum remains over all attack phases, not only critical phases.

Evaluate all eight LOSO folds at static k=100 and in the unchanged 12/hour replay. Use timestamp then hash ties. Save training counts, key scores, per-scenario metrics and replay traces. Check the vector score against an independently written scalar calculation; verify held-out count changes leave fitted scores unchanged; check replay integrity. Report results descriptively without extending the primary significance family. No forward or identifier-holdout version is included in this pass.
